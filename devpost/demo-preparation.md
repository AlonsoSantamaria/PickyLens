## Recording shot list

Target about 2–2.5 minutes, under three minutes per the official rules. Timing is an editing suggestion, not another hackathon requirement. Show the actual Web workspace in the first frame; no opening logo sequence.

| Scene | Capture needed from learner | Evidence to keep readable |
|---|---|---|
| 1. Web immediately | Open https://pickylens.neovantia.live/ and show the request/answer workbench | No login or code gate; actual request |
| 2. Review request | Activate Review my request; show the real assessment and human choice | Material findings; accepted changes or original request |
| 3. AI answer | Send the approved request and show the real answer | Answer belongs to that request; trim waiting time transparently |
| 4. Check answer | Activate Check this answer; expand one evidence item | Requirement statuses and supporting answer excerpt |
| 5. Outcome | If a real gap occurs, show targeted follow-up and verification when recorded; if all complete, show that honest result | Never manufacture a gap or describe an unexecuted repair as verified |
| 6. Gemini briefly | Show normal Gemini Chat, compact PickyLens control, one reviewed answer and adjacent evidence | Same everyday host; do not spend video time installing or entering a pass |

Spend most time on scenes 1–4. Keep Gemini to roughly 20–30 seconds. Omit CLI, Antigravity, setup, architecture and failed experiments. If fresh live footage is needed, budget it before agent-operated calls; the prior agent authorization is exhausted. Do not rerun simply to force a defect. A complete answer is a valid outcome. Do not substitute internal Replay or stubs while presenting the footage as live.

## Assets and capture mechanics

Ready: live Web URL, public source, released extension ZIP, existing glasses SVG (app/static/glasses.svg), this shot list. No new mascot/artwork is needed. Existing validation evidence is not a recorded demo video.

Learner supplies: Web screen recording, short Gemini screen recording, own English narration or captions, final edited video, and public video URL. Optional stills can be taken from the same footage if the actual form requests images; no unverified image-count requirement is imposed.

Use a readable desktop browser window, preferably 1080p recording. Keep request, assessment and evidence large enough to read. Hide unrelated tabs/account details; never record extension pass configuration, keys, terminal secrets or private History. Prepare extension access before recording. Preserve continuity when trimming model waits; do not splice different interactions to imply a result that did not occur.

Upload to YouTube or Vimeo with public visibility as stated by the rules. Test playback without signing in. Supply the URL for verification; live deployment does not replace the video.
