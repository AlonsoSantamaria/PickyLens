From a request to verified evidence

PickyLens quality-checks both sides of an AI exchange. The human approves intent; the application reviews the answer, prepares a targeted follow-up when useful, and verifies the combined result.

Main pieces

A server-rendered FastAPI workbench presents the interaction. Provider-neutral core functions perform PRE, POST, NEXT and VERIFY. The coordinator owns transitions; SQLite saves a current snapshot and an append-only event trace. An OpenAI adapter supplies model calls. Replay substitutes only the first response using the unchanged captured fixture.

Three-stop reference route

Reference route for independent navigation; this was not a separate interactive code tour.

1. Coordinate the answer check

app/services/interactions.py · search async def run

Interactions.run passes the approved intent and the correct response set into the shared evaluator. VERIFY includes both answers. It saves success only after evaluation completes.

2. Validate the assessment

app/core/evaluation.py · search async def evaluate

evaluate calls the injected provider, then checks intent version, complete requirement coverage, unchanged requirement text, and exact quoted evidence. Confirmed conflicts become Partial; unresolved conflicts become Needs review.

3. Save and display the evidence

app/storage/repository.py · search def finish

Repository.finish records the result while enforcing operation/revision boundaries. The workspace renders counts and expandable evidence; History retains the trace.

To change this, start here

  • Workspace wording and orientation: app/templates/workspace.html, app/static/workspace.js (render, syncOrientation), and app/static/styles.css. New-case and active-case presentation follows saved state.
  • Evaluation rules: app/core/evaluation.py and typed contracts in app/core/contracts.py. Model instructions live in app/providers/openai_adapter.py.
  • Another provider: implement Provider.generate_structured and Provider.generate_text from app/providers/base.py; preserve core contracts. Gemini browser host assumptions are isolated in extensions/browser/gemini-host.js; CLI adapters remain optional.
  • Retry, resume or supersession: app/services/interactions.py and app/storage/repository.py; begin with tests/test_recovery.py.
  • Replay compatibility: app/services/replay.py and tests/test_replay_compatibility.py. Preserve the fixture and provenance in app/fixtures/consultant_replay.v1.json.

A practice to reuse

The genuine response exposed inconsistent costs even though the initial POST judged its requirements complete. The learner authorized the material-quality-defect amendment while retaining the exact capture and prohibiting manufactured defects. Generic evaluation rules and synthetic contradiction tests followed, then one bounded live POST confirmed the captured defect.

Connect a human-owned requirement to two kinds of evidence: deterministic contract tests and bounded model observations. tests/test_consistency.py checks conflict statuses and rejects fabricated citations; test_only_first_response_is_replaced_and_full_trace_survives in tests/test_replay_flow.py proves that Replay still runs the later provider stages. Neither proves general semantic accuracy. See spec.md (Authorized Replay Quality-Defect Amendment) and live-verification.md.

Reuse: specify the invariant, delegate implementation behind a small interface, verify deterministic guarantees, and report model uncertainty separately. Schema validity and real quotations do not guarantee a correct judgment.

Run again

From the project root with the existing virtual environment:

.\.venv\Scripts\python.exe -m uvicorn devtools.stub_app:app --host 127.0.0.1 --port 8000
.\.venv\Scripts\python.exe -m pytest -q

The stub is synthetic and makes zero live calls. Open http://127.0.0.1:8000/. For the real application, replace devtools.stub_app:app with app.main:app; review/repair actions use the configured API. Run one worker per SQLite instance. See README.md for environment and recovery instructions.
